# TAKATAK Cross-Project Design Preferences

## Goal
TAKATAK sites should feel intentionally designed, polished, modern and animated rather than like unmodified templates.

## Reusable visual direction
Across projects, prioritize:
- clean, sharp layouts
- strong visual hierarchy
- polished headers and hero sections
- high-quality imagery
- responsive cards and carousels
- motion/transition polish
- tasteful shifting/animated visual states
- refined pop-up/modal experiences
- mobile-first navigation
- professional loading/empty/error states
- consistent spacing and typography
- strong call-to-action hierarchy

## Shared experience patterns
When applicable, reusable site patterns may include:
- TAKATAK OTP/login surfaces
- sponsor/advertising placements
- AdSense-compatible placements where appropriate
- social links/connections
- animated menus
- promotional carousels
- location/business cards
- multilingual navigation
- responsive dashboards

## Rule
Visual work must not silently change domain logic, backend contracts or authorization rules. UI modernization is a separate concern from business logic unless a project explicitly combines both scopes.

## Lovable role
Lovable is primarily useful for fast visual/product implementation and exportable UI. Production ownership and source-of-truth remain in TAKATAK-controlled GitHub/infrastructure.
